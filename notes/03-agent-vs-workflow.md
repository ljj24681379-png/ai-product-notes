# Agent 什么时候应该自主决策，什么时候应该使用固定工作流

## 问题

Agent 产品常被描述为“让模型自己规划并完成任务”。自主性很有吸引力，但并不是越多越好。固定工作流稳定、可预测，却难以覆盖开放问题；完全自主的 Agent 灵活，却容易走弯路、遗漏步骤，甚至在高风险节点做出不可逆动作。产品设计的关键不是二选一，而是决定自主性放在哪里。

## 真实现象

同一个研究任务里，资料来源和分析路径可能随主题变化，适合让 Agent 动态规划；但发布报告前的来源检查、敏感信息检查和人工确认不应随意跳过。文件生成任务可以自主选择内容结构，但“生成后必须校验文件可打开”更适合固定为硬门槛。

许多失败并非模型不会推理，而是流程没有定义边界。工具参数错误后仍继续执行，是因为失败没有阻断；缺少第二个交付物，是因为计划阶段没有形成清单；研究报告缺少来源，是因为审核只是一句 Prompt，而不是独立步骤。

## 为什么会发生

团队容易把 Agent 和 Workflow 当作两种技术架构，却忽略它们首先是责任分配方式。让 Agent 自主，意味着允许它决定下一步并承担更多不确定性；使用固定流程，意味着产品提前规定路径，并为边界情况设计分支。

如果任务目标开放、信息路径未知、错误可恢复，自主规划的价值更大。如果规则明确、错误成本高、过程需要审计，确定性流程更合适。多数真实产品会是混合形态。

## 方法

我会从四个维度判断。第一是目标是否清晰：目标模糊时，先让人确认而不是让 Agent 猜。第二是路径是否稳定：稳定重复步骤应固化为工作流。第三是错误是否可逆：发送、删除、付款等动作需要权限和确认。第四是结果是否可验证：能自动校验的节点可以给 Agent 更多尝试空间。

一种实用设计是“固定骨架 + 局部自主”。骨架规定输入检查、关键工具、验证和交付门槛；Agent 在检索范围、任务拆分、内容组织和修复策略上自主选择。每个自主节点都要有预算、停止条件和失败出口。

## 产品判断

Agent 的价值不在于把流程图全部删除，而在于处理流程图难以穷举的变化。工作流的价值也不是限制智能，而是把责任、风险和验收标准固定下来。

因此，好的产品不会宣传“完全自主”，而会清楚说明：哪些决定交给 Agent、依据是什么、哪些步骤不能跳过、失败后谁接管。自主性不是功能卖点，而是一种需要按风险分配的产品资源。
